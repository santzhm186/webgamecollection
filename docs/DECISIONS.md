# 决策记录（ADR）

> 记录**为什么这样设计**，而不只是设计成什么样。
> 目的：半年后（或新贡献者）看到某个奇怪的约定时，能查到它当时的取舍，
> 而不是凭猜测把它"顺手改回去"。
>
> 格式：`决策 / 背景 / 选择 / 被否掉的方案 / 代价 / 状态`
> 状态说明：**已定**（短期内不改）、**暂缓**（接口留好、实现待做）、**待定**（开放问题）
>

## D1 · 依赖策略：运行时禁止 `import` npm 包，第三方库必须内联（vendored）

> **v0.3 修订。** 原文是"零运行时依赖，不引入打包器"。v0.3 为 3D 模型管线引入了
> Three.js 与 esbuild，原文已不成立 —— 但**核心约束（运行时零 npm import）仍然保留**，
> 只是允许"构建期生成、运行期内联"这一条通路。修订原因与代价见下，修订记录见文末。

- **背景**：项目要在 GitHub 开源、接受多人贡献，且游戏数量会增长（可能到几十个）；
  v0.3 起需要共享 3D 模型（24 个 GLB，见 [D16](#d16--共享低多边形模型库gltf-导出--sprite-渲染)）。
- **选择**：
  1. **运行时禁止 `import` npm 包** —— 游戏与宿主代码里不得出现 `from 'three'` 之类的裸模块导入。
  2. 第三方库以**单文件 vendor** 形式放 `public/lib/`，且**只能动态 import**：
     `await import('../../../public/lib/three.mjs')`，这样 2D 降级与 Node 测试都不受影响。
  3. 构建期允许 `esbuild`，唯一用途是把 `three.module.js` 打成 `public/lib/three.mjs`
     （`postinstall` 脚本）。**不允许**把 esbuild 用于应用代码的打包。
  4. 只允许一个第三方运行时库（Three.js）。第二个需要重新论证。
- **被否掉的方案**：
  - 直接 `import 'three'` —— 需要打包器或 importmap，Node 测试环境无法解析，且首屏被迫加载 742KB。
  - 从 CDN 引 three —— 断网 / 内网 / 强 CSP 环境下不可用，违背"本地能跑"。
  - 完全不引入 3D —— 放弃模型库的复用价值；而 sprite 降级路径让成本可控。
  - 引入 Vite / React —— 本项目没有需要框架解决的问题（见 D4 用 JSDoc + 测试代替类型编译）。
- **代价**：
  - 供应链面从 0 变成 **1**（three）。这是本轮最大的取舍，必须在 review 时守住"只有一个"。
  - `public/lib/three.mjs` 742KB（贪婪加载时才下载，不进首屏）。
  - **首次运行需要 `npm install`**（生成 vendor）。仓库当前已含生成物，所以 clone 即可跑 ——
    但这也带来一个仓库一致性隐患：`public/lib/` 同时在 `.gitignore` 里，见文末"已知问题"。
- **换来什么**：24 个模型可跨 6 个游戏复用；2D Canvas 玩法不必改架构就能用上 3D 资产；
  无 WebGL 时安全降级；首屏体积仍与是否用 3D 无关。
- **状态**：已定（v0.3 修订）。新增依赖需在 PR 里单独论证（见 [协作文档](SCALING-AND-CONTRIBUTING.md) §5）。

## D2 · 纯静态优先，但存储层做成可替换适配器

- **背景**："数据保存库 + 排行榜"这两个需求可以指向完全不同的架构（本地文件 vs 服务端）。
- **选择**：先做纯静态（成绩存本机），但**所有持久化经 `StorageAdapter` 端口**，
  且端口**全部异步**（`Promise`）。排行榜 UI 通过 `capabilities.remote` 决定是"本地模式"还是真榜单。
- **被否掉的方案**：
  - 直接上 Node + SQLite —— 部署不能再丢到静态托管，且当前没有跨用户需求。
  - 同步的存储接口 —— `localStorage` 是同步的，写起来更省事，但**这是不可逆决策**：
    将来接 IndexedDB / SQLite / HTTP 时要改遍每一个调用点。
- **代价**：现在要多写 `await`，且适配器要维护 `capabilities` 与配额降级逻辑。
- **状态**：已定（方向）。**实现未完成**：`src/storage/adapter.js` 已定义端口与 10 条契约用例，
  但 `local` / `memory` 适配器、`ScoreStore`、`ProgressStore` 尚未实现；
  `app.mjs` 仍直接读写 `localStorage`（P1 会收口）。

## D3 · 用户身份：匿名设备 ID + 可自选昵称

- **背景**：排行榜需要"谁的成绩"，但纯静态下没有可信的身份。
- **选择**：首访生成 `u_<uuid>` 存本机；玩家可自选显示名；成绩记录里存**昵称快照**。
- **被否掉的方案**：
  - 纯匿名无名 —— 排行榜只能显示"我的最好成绩"，玩家看不到自己在人群里的位置。
  - 账号体系（用户名 + 密码）—— 纯静态下只能做到"弱身份"（可伪造），
    却要付出注册/登录/会话/找回的复杂度，收益不匹配。
- **代价**：改名只影响之后的记录；本地身份可被清理浏览器数据而丢失。
- **状态**：已定。实现待 P1（`src/services/identity.js`）。

## D4 · 契约层 + 单一共享入口（`host-surface.js`）

- **背景**：游戏必须能独立于宿主存在，否则第二个贡献者写游戏时会顺手 import 宿主内部模块，
  边界会一点点烂掉（今天 import i18n，明天 import score-store，后天直接读 localStorage）。
- **选择**：
  - 所有契约（`GameManifest` / `GameEngine` / `GameRenderer` / `GameContext` / `ScoreRecord` …）
    集中在一个**无运行时代码**的文件 [`src/core/contracts.js`](../src/core/contracts.js)。
  - 游戏**只允许** import [`src/core/host-surface.js`](../src/core/host-surface.js)
    与 [`src/ui/scene/primitives.js`](../src/ui/scene/primitives.js)；
    由 `tests/dictionary.test.mjs` 的 T5 用例机械校验。
- **被否掉的方案**：
  - 类型用 TypeScript —— 引入编译步骤（见 D1）。
  - 让游戏自由 import —— 无法在 CI 阶段拦截越界。
- **代价**：`host-surface.js` 需要人工维护（新增能力要记得转发）。
- **状态**：已定。**已知取舍**：JSDoc 字面量联合类型与运行时枚举是两份定义，
  由测试断言二者一致（见 D13）。

## D5 · 注册表用「构建期生成的显式索引」，不用运行时扫目录

- **背景**：游戏数量会增长，需要"加一个游戏"尽可能简单。
- **选择**：`games/index.js` 提供**动态 import 加载器数组**；
  当前手写 3 行，将来由 `scripts/games-index.mjs` 扫描生成并挂到 `predev` / `prebuild`。
- **被否掉的方案**：
  - 运行时 `fetch` 扫目录 —— 纯静态托管没有目录列表接口。
  - `import.meta.glob` —— 需要打包器（见 D1）。
  - 静态 import 全部 manifest —— 拖着整个游戏的代码进首屏。
- **代价**：多一个文件要维护；生成器未上线前需手写。
- **状态**：已定（接口按"生成式"设计）。生成器待做。

## D6 · manifest 声明 + 动态 import；注册表负责隔离

- **背景**：一个贡献者的语法错误不能让整站白屏。
- **选择**：每个游戏导出 `manifest.js`（无副作用、可静态分析、重活写成 `() => import(...)`）；
  注册表 `load()` 内部 `try/catch` **逐个隔离**，坏模块只让那一张卡片降级；
  `validateManifest()` 一次报全所有问题。
- **被否掉的方案**：让 manifest 直接导出实例或数据 —— 首页加载会被拖慢，且无法隔离。
- **代价**：所有游戏要包一层动态 import；注册表需要处理"已加载/加载失败/已缓存"三种状态。
- **状态**：已定，已实现（[`src/core/registry.js`](../src/core/registry.js)）。

## D7 · 引擎不碰 DOM；渲染器无状态

- **背景**：需要自动化验证玩法正确性（穷举路线、穷举操作顺序、证明可解性）。
- **选择**：
  - `games/<id>/engine.js` **禁止**出现 `document` / `window` / `localStorage` / `requestAnimationFrame`。
  - 状态全在引擎实例上；渲染器只是 `(engine, theme) => 画面`，`destroy()` 必须解绑。
- **被否掉的方案**：把交互与绘制写在引擎里 —— 那样只能在浏览器里手工测。
- **换来什么**：**能在 Node 里穷举 224 条冲关路线、918 种拉针顺序、6 个棋盘的全部解法**；
  也是将来做服务端重放校验（反作弊）的前提。
- **状态**：已定。由 `tests/dictionary.test.mjs` T5/T6 与游戏测试共同保障。

## D8 · 多人游玩：接口预留，不实现

- **背景**：目标里有"同一游戏同时多人游玩"，但当前不做。
- **选择**：把设计钉死在 [`src/core/multiplayer.js`](../src/core/multiplayer.js)，
  三条不可动摇的原则：
  1. **一个引擎实例 = 一整局**（不是每人一个实例），因此 `GameEngine` 契约不变。
  2. **补丁里只允许有动作，绝不允许有状态** —— 否则确定性没了，重放校验也没了。
  3. **回合同步交给引擎**（`activePlayers()`），传输层不理解任何玩法规则。
- **被否掉的方案**：
  - 现在就实现 hotseat / bot 适配器 —— 已实现过又按需求删除（见下方"修订记录"）。
  - 现在就设计联机协议 —— 没有真实需求驱动，容易设计错。
- **代价**：预留的接口会"腐烂"成看起来能用其实不能用 —— 因此有 T7 测试
  校验"仍是预留状态"，并在契约文末写明接入路线与推荐顺序。
- **状态**：**暂缓**。不声明 `players` 的游戏即单人，向后兼容。

## D9 · 不写游戏专属分支：宿主只认契约

- **背景**：旧 `app.mjs` 里到处是 `if (id === 'runner')`，第二个游戏就在增加分支。
- **选择**：P3 把三条硬编码分支全部消除，改为契约驱动：
  按 `renderer.kind` 分派、按 `session.timeDriven` 决定是否托管 rAF、
  HUD 由 `engine.hud()` 自述、结算由 `session.poll()` 统一判定。
- **代价**：引擎必须实现 `hud()` 与 `metrics()`（能力不足时宿主会少显示东西，而不是报错）。
- **状态**：已定，已实现。底线：**`app.mjs` 里出现任何"某个游戏才有的东西"都是设计错误**。

## D10 · 卡片与游戏壳由注册表生成（`<template>` + 事件委托）

- **背景**：卡片写死在 `index.html` 时，新增游戏必须同时改 HTML 与 JS，容易漏。
- **选择**：卡片模板留在 `index.html` 的 `<template>` 里，由 `app.mjs` 按注册表克隆；
  文案键因此**仍能被 T4 扫描器检查到**（写在 JS 模板字符串里就检查不到）。
  打开游戏的入口用**事件委托**，因为卡片会被反复重建。
- **被否掉的方案**：
  - 卡片完全写在 JS 里 —— 文案键失去静态检查。
  - 逐个 `addEventListener` —— 绑定时元素还不存在／重建后监听器丢失
    （真实踩过：卡片点了完全没反应，且无任何报错）。
- **状态**：已定，已实现。

## D11 · 四层字典，加一个「中文机器值」的已知偏离

- **背景**：同一个概念曾出现 3 个不同拼写；`'入门'` 在 `engine.mjs` 里独立出现 12 次；
  `category: '01 / ACTION'` 把展示序号与筛选键混成一个字符串。
- **选择**：字典分四层（闭合枚举 / 共用显示文案 / 多语言文案 / 游戏私有字典），
  判据是一句话：**宿主需要在代码里 `if` 它吗？**
  详见 [命名与字典约定](NAMING-CONVENTIONS.md)。
- **已知偏离**：`DIFFICULTY` 的**索引是中文**（`'入门'`），因为它同时是关卡数据里的机器值，
  且被三个游戏共享。显示层已用 `difficultyLabel()` 做映射（英文语境显示 `Beginner`），
  **不影响使用**；改为英文键要同步改三套关卡数据，排在 P4。
- **状态**：已定，已实现（341 个文案键 × 2 语言，覆盖 6 个游戏；14 组闭合枚举）。

## D12 · 多语言：文案键 + 三层渲染，`?lang=` 不写持久化

- **背景**：首页要加语言选择。这类功能最容易烂尾的方式是"切了语言但游戏内文案不变"。
- **选择**：
  - 所有面向玩家的字符串必须有键，新增键必须补全**所有**语言（T1 强制）。
  - 切换语言时**三处都要更新**：HTML 静态文案（`data-i18n`）、JS 动态文案（重渲染）、
    **引擎生成的文案**（按当前状态用 `t()` 重算）。
  - 正在进行的对局**不重建**（会丢进度），只刷新文案。
  - `?lang=en` 可直接指定语言且**不写入**持久化设置（便于分享链接与端到端测试）。
  - 搜索索引包含**所有语言**的名称 —— 中文界面下搜 "unscrew" 也应该找得到。
- **被否掉的方案**：切换语言时重建对局（语义最干净但会丢玩家进度）。
- **状态**：已定，已实现。

## D13 · 数据与排行榜：复合键、昵称快照、进度与成绩分离

- **背景**："按 ID 保存用户成绩" + "排行榜读取成绩列出排名"。
- **选择**：
  - 成绩记录 `id = ${userId}:${gameId}:${level}` —— 天然幂等，重复提交是**更新**而非插入。
  - 存**昵称快照**：榜单渲染不需要 join 用户表，改名也不会让历史名次集体变动。
  - 存 `engineVersion`：改了数值规则后，新旧成绩不会静默混进同一个榜。
  - **进度与成绩分离**：`ProgressRecord`（星级/解锁）可由成绩派生，成绩是原始事实。
  - 排行榜采用**竞技排名**（1,2,2,4）；排序必须是**确定性全序**：
    `score desc → durationMs asc → updatedAt asc → userId asc`。
  - 本地模式的 UI 必须**诚实标注**"仅本机成绩"，不假装有他人排名。
- **被否掉的方案**：名次落库（插入一条要回写全榜，写放大严重）。
- **状态**：已定（设计）。实现待 P1/P5。

## D14 · 命名：字符串键用 camelCase，其余一切用 kebab-case

- **背景**：多人协作下命名不一致会持续制造摩擦，而这类问题 review 时最难发现。
- **选择**（完整清单见 [项目约定](../CONVENTIONS.md)）：
  文案键段内 camelCase（`app.footerCopyright`）；游戏 id / 枚举值 / CSS 类 / 文件名
  一律 kebab-case；导出**用具名导出**（与 `node:test` 风格一致，便于 greppability）。
- **状态**：已定，由 T1 与枚举测试校验。

## D15 · 文档与测试同步：约定必须有执行者

- **背景**：写在文档里的约定如果没人执行，三个月后就会与实际不符。
- **选择**：**每条约定都要能指向一个会失败的测试**。
  字典、契约、注册表、会话与宿主交互均有自动化执行者；当前数量见 [项目约定](../CONVENTIONS.md) §6。
  改约定必须同时改文档与测试，否则 CI 会拦下来。
- **状态**：已定。当前对照表见 [项目约定](../CONVENTIONS.md) §6。

## D16 · 共享低多边形模型库（glTF 导出 + sprite 渲染）

- **背景**：v0.3 需要"共享资源库包括模型"。有两个完全不同的方向：真 3D 场景，
  还是把 3D 资产**降维**给现有 2D 玩法用。
- **选择**：**数据一份、两处受益**的管线：

  ```
  src/models/arcade-kit.js       共享模型库（MATERIALS + MODELS，纯数据，无规则）
        │  scripts/build-models.mjs（Node 侧用 three 离屏渲染/导出）
        ▼
  public/assets/models/*.glb     24 个模型 + manifest.json
        │                         （version / format: glTF 2.0 / units: metres / up: +Y / forward）
        ▼
  src/ui/scene/three-models.js   运行时：WebGL 离屏渲染成 sprite（getAssetSprite）
        │                         无 WebGL 时**安全降级**为 2D 绘制
        ▼
  games/*/render.js              2D Canvas 直接当 sprite 用（士兵、金币、货箱…）
  ```

- **为什么是 sprite 而不是 3D 场景**：
  - 6 个游戏全部是 2D Canvas / SVG 玩法，改造为 3D 场景等于重写；
  - sprite 让"同一套模型"立刻被多个游戏复用（manifest 里每个模型带 `reuse: [runner, pins, shooter]`）；
  - 运行时成本可控：只有真正需要模型时才动态加载 three（D1），且每张 sprite 只渲染一次。
- **被否掉的方案**：
  - 直接上 3D 场景（`scene3d/`）—— 需要重写玩法与碰撞，收益不匹配（`src/scene3d/` 仍为空）。
  - 用手绘 SVG 代替模型 —— 模型库的价值在"一处建模、多游戏复用"，手绘无法复用几何。
- **代价**：模型需要离线构建（`npm run models`）；GLB 与 manifest 必须同步（有测试校验
  GLB 头、三角形数、包围盒与 definitions 一致）；引入 three（见 D1 的供应链代价）。
- **状态**：已定，已实现（24 个模型；骨骼动画与 `ResourceManager` 未实现）。

| **依赖策略（D1）** | 运行时与开发期**都不装 npm 包**，不引入打包器 | 允许 Three.js 作为**唯一**第三方运行时库，但必须 vendor 到 `public/lib/` 且只能动态 import；构建期允许 esbuild 生成 vendor | v0.3 的 3D 模型管线需要 three；为保住"运行时零 npm import、首屏不加载 3D"，选择内联而非裸导入 |
| 多人适配器 | 实现 `hotseat-transport.js` 与 `bot-transport.js`（约 270 行） | **全部删除**，只留契约与接入路线 | 需求方明确"先不添加，只做预留"。空目录也会误导，故连目录一起删 |
| `art.mjs` | 宿主级冲关渲染文件 | **删除**，内容迁入 `games/runner/render.js` 与 `src/ui/scene/primitives.js` | 渲染属于游戏；共享原语属于共享层 |
| `engine.mjs` | 三合一规则文件 | **过渡文件**，只剩 pins/screws，P4 删除 | runner 已迁走；保留是为了让三个游戏都能走同一套注册表 |
| `PIN_LABELS` | 引擎导出的中文常量对象 | `games/pins/dictionary.js` 里的 `pinLabel()` 函数 | 机关名是游戏私有词汇；常量在切换语言后会过期 |
| `SCREW_RULES` | 螺丝关卡常量 | 更名 `SCREW_LEVEL_META` | 它描述关卡元信息而非"规则"，与 `SCREW_LEVELS`（布局）成对 |
| `kind` 字段 | `Renderer.kind` 与 `StorageAdapter.kind` 同名 | `RENDERER_KIND` / `STORAGE_KIND` | 语义无关却共用命名，调用方无法区分 |
| 卡片序号 | `category: '01 / ACTION'` | `category: 'action'` + `order: '01'` | 展示序号与筛选键混成一个字符串，导致三处各写一份 |
